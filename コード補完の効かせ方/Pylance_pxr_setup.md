# Isaac Sim スクリプトで Pylance のエラーを消す手順

Isaac Sim 用の Python スクリプトを VS Code で書くと、実行はできるのに
`"Xform" はモジュール "pxr.UsdGeom" の既知の属性ではありません` などのエラーが大量に出る問題への対処手順。

## 0. この手順で使うパス

環境によって変わるので、最初に自分の環境での値を確認しておく。

| 呼び名 | 何のパスか | この環境での例 | 確認方法 |
|---|---|---|---|
| `ISAAC_ROOT` | Isaac Sim のインストールフォルダ。`isaac-sim.bat`, `kit\`, `extscache\` がある場所 | `C:\isaacsim-6.0.2` | `isaac-sim.bat` があるフォルダ |
| `ISAAC_PY` | Isaac Sim 同梱の Python（3.12） | `ISAAC_ROOT\kit\python\python.exe` | 左記の場所にある |
| `USD_LIBS` | Isaac Sim の USD 本体（型 stub `.pyi` 付きの `pxr`）が入っている拡張 | `ISAAC_ROOT\extscache\omni.usd.libs-1.0.3+187cf21b.wx64.r.cp312` | `extscache\omni.usd.libs-*`（バージョン部分は環境ごとに違う） |
| `OTHER_PXR` | 別途入れた USD（自前ビルド・pip の usd-core など）。**あれば**今回の問題の原因になる | `C:\BuiltOpenUSD\lib\site-packages` | PowerShell で `$env:PYTHONPATH` を表示する。そこに `pxr` フォルダがあれば該当 |
| `USER_SETTINGS` | VS Code のユーザー設定 | `%APPDATA%\Code\User\settings.json` | コマンドパレット →「Preferences: Open User Settings (JSON)」 |
| `WS_SETTINGS` | ワークスペースの設定（ユーザー設定より優先される） | `ISAAC_ROOT\.vscode\settings.json` | Isaac Sim に最初から入っている |

前提: VS Code では **`ISAAC_ROOT` をフォルダとして開いている**こと（「ファイル → フォルダーを開く」）。
`WS_SETTINGS` と後で作る `typings` フォルダは、このフォルダを基準に読み込まれる。

## 1. 原因（3つが重なっていた）

| # | 症状 | 原因 |
|---|---|---|
| A | 「〜の種類が不明です」が大量に出る | `USER_SETTINGS` で `python.analysis.typeCheckingMode` が `strict`。Isaac Sim の stub は戻り値が `Any` のものが多く、strict では型が分からない箇所がすべてエラーになる |
| B | `pxr.UsdGeom.Xform` / `pxr.Gf.Vec3f` などが「既知の属性ではありません」 | `OTHER_PXR` が環境変数 `PYTHONPATH` に入っていた。そちらの `pxr` は `__init__.py` を持つ通常パッケージで stub が無い。Isaac Sim の `pxr` は `__init__.py` を持たない名前空間パッケージ。Pylance は両方見つかると、`extraPaths` の順番に関係なく通常パッケージ側を採用するため、stub の無い方が使われていた |
| C | `get_stage` / `next_update_async` が「属性にアクセスできません」 | どちらも実行時に Python 側でクラスへ後付けされるメソッドなので、`.pyi` に載っていない |

## 2. 手順

### 手順1: 型チェックの厳しさをワークスペースだけ緩める（原因A）

`WS_SETTINGS` に次の1行を追加する（`"python.languageServer": "Pylance",` の下など、`{ }` の中ならどこでもよい）。

```jsonc
"python.analysis.typeCheckingMode": "standard",
```

ユーザー設定の `strict` は他のプロジェクト用にそのまま残る。

### 手順2: `pxr` 用のスタブフォルダを作る（原因B）

**`OTHER_PXR` が無い環境ではこの手順2〜3は不要。**

Isaac Sim の `pxr` サブモジュールへのリンク（Windows のジャンクション）を集めた `ISAAC_ROOT\typings\pxr\` を作る。
`__init__.pyi` を置いて通常パッケージ扱いにするので、`OTHER_PXR` より優先される。
Isaac Sim 本体のファイルはコピーも変更もしない。

1. 下のスクリプトを `ISAAC_ROOT` の **1階層下のフォルダ**に保存する（例: `ISAAC_ROOT\CodeByClaude\gen_pxr_typings.py`）。
   スクリプトは「自分の親の親フォルダ」を `ISAAC_ROOT` とみなす。
2. `ISAAC_PY` で実行する（`os.path.isjunction` を使うので Python 3.12 以上が必要）。

   ```powershell
   cd ISAAC_ROOT
   .\kit\python\python.exe CodeByClaude\gen_pxr_typings.py
   # → "56 modules linked into ...\typings\pxr" のように表示される（数は環境による）
   ```

```python
# Pylance 用に typings/pxr を生成する（Isaac Sim の pxr サブモジュールへのジャンクションを集めたスタブパッケージ）。
# システムの PYTHONPATH にある別ビルドの pxr（stub 無し）が Isaac Sim の pxr を隠してしまう問題の回避策。
# 使い方: python CodeByClaude/gen_pxr_typings.py   （extscache の拡張を更新したら再実行）
import glob
import os
import shutil
import subprocess

ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
DEST = os.path.join(ROOT, "typings", "pxr")

if os.path.isdir(DEST):
    # ジャンクションはリンクだけ消す（rmdir はリンク先を消さない）
    for name in os.listdir(DEST):
        path = os.path.join(DEST, name)
        if os.path.isdir(path):
            os.rmdir(path) if os.path.islink(path) or os.path.isjunction(path) else shutil.rmtree(path)
        else:
            os.remove(path)
os.makedirs(DEST, exist_ok=True)

# 通常パッケージ扱いにして、他の場所の pxr より優先させる
with open(os.path.join(DEST, "__init__.pyi"), "w", encoding="utf-8") as f:
    f.write("# generated by CodeByClaude/gen_pxr_typings.py\n")

sources = glob.glob(os.path.join(ROOT, "extscache", "omni.usd.libs-*", "pxr")) + glob.glob(
    os.path.join(ROOT, "extscache", "omni.usd.schema.*", "pxr")
)
count = 0
for src in sources:
    for name in os.listdir(src):
        target = os.path.join(src, name)
        link = os.path.join(DEST, name)
        if not os.path.isdir(target) or name.startswith("__") or os.path.exists(link):
            continue
        subprocess.run(["cmd", "/c", "mklink", "/J", link, target], check=True, stdout=subprocess.DEVNULL)
        count += 1

print(f"{count} modules linked into {DEST}")
```

リンク元は `USD_LIBS\pxr\*`（Usd, UsdGeom, Gf など）と `ISAAC_ROOT\extscache\omni.usd.schema.*\pxr\*`（PhysxSchema など）。
拡張のバージョン部分はワイルドカードで探すので、パスを書き換える必要はない。

### 手順3: Pylance にスタブフォルダを教える（原因B）

`WS_SETTINGS` に追加する。パスは `ISAAC_ROOT` からの相対パス。

```jsonc
"python.analysis.stubPath": "typings",
```

### 手順4: VS Code を再読み込みする

コマンドパレット（Ctrl+Shift+P）→「**Developer: Reload Window**」。
**設定を変えただけでは反映されなかった**ので、この操作は必須。

### 手順5: stub に無いメソッドはコード側で補う（原因C）

実行時に後付けされるメソッドは、変数に型注釈を付け、その行だけエラーを抑える。

```python
from pxr import Usd
import omni.usd, omni.kit.app

stage: Usd.Stage = omni.usd.get_context().get_stage()  # pyright: ignore[reportAttributeAccessIssue]
await omni.kit.app.get_app().next_update_async()  # pyright: ignore[reportAttributeAccessIssue]
```

`pxr` の stub は戻り値が `typing.Any` のものが多い（`Define()` など）。
`sphere: UsdGeom.Sphere = UsdGeom.Sphere.Define(...)` のように変数側にも型を書くと補完が効くようになる。

## 3. 確認方法

- Problems パネル（Ctrl+Shift+M）で、対象ファイルに Pylance のエラーが無いこと。
- `pxr.UsdGeom` の上で F12（定義へ移動）を押すと、`ISAAC_ROOT\typings\pxr\UsdGeom\__init__.pyi` が開くこと。
  `OTHER_PXR` 側の `__init__.py` が開く場合は、手順2〜4が効いていない。

## 4. 試したが効かなかった方法

- **`ISAAC_ROOT\.env` に `PYTHONPATH=` と書いて空にする**: VS Code の Python 拡張は、この値を Pylance のモジュール検索に渡さなかった。
- **`WS_SETTINGS` の `python.analysis.extraPaths` を調整する**: 原因Bのとおり通常パッケージが優先されるので、順番を変えても解決しない。

## 5. 注意点

- **Isaac Sim の拡張を更新したら手順2のスクリプトを再実行する。** `extscache` のフォルダ名が変わると、リンク切れになる。
- **実行時は別問題として残っている。** `ISAAC_ROOT\setup_python_env.bat` は `SET PYTHONPATH=%PYTHONPATH%;...` で、`OTHER_PXR` を Isaac Sim のパスより前に置く。そのため `python.bat` で実行するスタンドアロンのスクリプトでは、`OTHER_PXR` の `pxr` が読み込まれる可能性がある。
  GUI 内で実行するスクリプト（VS Code の Run / Script Editor）は問題なく動くことを確認済み。

## 6. 元に戻す方法

1. `ISAAC_ROOT\typings` フォルダを削除する（中身はジャンクションなので、リンク先の Isaac Sim 本体は消えない）。
2. `WS_SETTINGS` から手順1と手順3で追加した2行を消す。
3. Reload Window を実行する。
