# ホットキー

## 解決したい課題：同じキーを複数の拡張機能が奪い合う

矢印キーは、既定では3Dビューのカメラ移動に割り当てられている。自作モードで矢印キーを関節角度の変更に使うなら、その状態のときだけ横取りする必要がある。

各拡張機能が独自にキーボード入力を直接読むと、どちらが先に受け取るかが決まらない。さらに、テキスト入力欄にフォーカスがあるときにも横取りしてしまうと、文字が打てなくなる。

## 解決の方針：登録簿に登録し、有効条件を添える

Kit は `omni.kit.hotkeys.core` という拡張機能で、キーと動作の対応を一括管理する。この拡張機能は「キーバインド・アクション・フォーカスウィンドウを組にしたホットキー」を扱うものと説明されている [^1]。

## 仕組み

### アクションとホットキーが分かれている

| 概念 | 何を持つか | 提供する拡張機能 |
|---|---|---|
| アクション | 「実行する処理」に ID を付けたもの | `omni.kit.actions.core` |
| ホットキー | 「どのキーで、どのアクションを、どの条件で呼ぶか」 | `omni.kit.hotkeys.core` |

分けてある理由は、同じ処理をメニュー・ボタン・キーの3経路から呼べるようにするためになる。処理の実体は1つで、呼び出し口が3つになる。

### グローバルとローカルの区別

ホットキーには2種類ある [^1]。

| 種類 | 効く範囲 | 優先度 |
|---|---|---|
| グローバル | アプリ全体 | 低い |
| ローカル | 指定したウィンドウにフォーカスがあるときだけ | 高い |

同じキーがグローバルとローカルの両方に定義されている場合、ローカルが優先される [^1]。矢印キーをビューポート上に限定したい場合は、ローカルとして登録する。

### 登録に必要な4つの情報

公式の使用例に出てくる形は次のとおり [^2]。

```python
hotkey_registry = omni.kit.hotkeys.core.get_hotkey_registry()
hotkey_registry.register_hotkey(
    "your_extension_id",
    "CTRL + N",
    "execute_action_extension_id",
    "execute_action_id",
    filter=HotkeyFilter(windows=["Test Window"]),
)
```

引数の意味は次のとおり。

| 位置 | 内容 |
|---|---|
| 1番目 | このホットキーを登録する拡張機能の ID。まとめて解除するときの単位になる |
| 2番目 | キーの組み合わせを表す文字列 |
| 3番目 | 呼び出すアクションを提供する拡張機能の ID |
| 4番目 | 呼び出すアクションの ID |
| `filter` | 有効条件。`windows` にウィンドウ名を並べるとローカルホットキーになる |

解除は2通りある [^2]。

| 呼び出し | 範囲 |
|---|---|
| `deregister_hotkey(...)` | 1個ずつ |
| `deregister_all_hotkeys_for_extension("拡張機能のID")` | その拡張機能が登録したものすべて |

モードから抜けるときに矢印キーの束をまとめて外す用途では、後者が使える。

### ツールバー側にも簡易なホットキー機能がある

`omni.kit.widget.toolbar` は `Hotkey` というクラスを持っている [^3]。[[03_ツールバーの構造]] で見た `SimpleToolButton` の `hotkey` 引数はこれを使っている。

`Hotkey` の第4引数は「今このホットキーが有効か」を返す判定関数で、公式サンプルでは `_is_in_context` を渡している（[[05_ツールバーのコンテキスト]] 参照）[^4]。ツールバーのボタンと1対1で対応するキーであれば、こちらのほうが記述量が少ない。

用途による使い分けは次のようになる。

| 用途 | 使うもの |
|---|---|
| ツールバーのボタン1個と対応するキー | `omni.kit.widget.toolbar.Hotkey` |
| ボタンを持たない操作のキー、ウィンドウ限定のキー、まとめて解除したいキーの束 | `omni.kit.hotkeys.core` |

## 実装

### 登録して、解除して、解除を確認する

Script Editor に貼り付ける全文になる。アクションの登録も含めて1つにまとめてある。

```python
# ===== 目的：矢印キーをアクションに結び付け、登録と解除を確認する =====
import carb
import omni.kit.actions.core
import omni.kit.hotkeys.core

EXT_ID = "demo.joint.hotkeys"        # 解除の単位になる ID
ACTION_ID_UP = "joint_angle_up"
ACTION_ID_DOWN = "joint_angle_down"

_action_registry = omni.kit.actions.core.get_action_registry()
_hotkey_registry = omni.kit.hotkeys.core.get_hotkey_registry()


def _on_up():
    carb.log_warn("[hotkey] 上矢印：関節角度を増やす")


def _on_down():
    carb.log_warn("[hotkey] 下矢印：関節角度を減らす")


# アクションを登録する（処理の実体に ID を付ける）
_action_registry.register_action(EXT_ID, ACTION_ID_UP, _on_up, display_name="関節角度 +")
_action_registry.register_action(EXT_ID, ACTION_ID_DOWN, _on_down, display_name="関節角度 -")

# ホットキーを登録する（キーとアクションを結び付ける）
_hk_up = _hotkey_registry.register_hotkey(EXT_ID, "UP", EXT_ID, ACTION_ID_UP)
_hk_down = _hotkey_registry.register_hotkey(EXT_ID, "DOWN", EXT_ID, ACTION_ID_DOWN)

carb.log_warn(f"[hotkey] registered: up={_hk_up}, down={_hk_down}")
```

実行後に上下の矢印キーを押すと、Console に次の行が出る。

```text
[hotkey] registered: up=<Hotkeyオブジェクト>, down=<Hotkeyオブジェクト>
[hotkey] 上矢印：関節角度を増やす
[hotkey] 下矢印：関節角度を減らす
```

この状態では矢印キーがアプリ全体で横取りされる。ビューポートのカメラ移動が効かなくなるので、確認したら必ず解除する。

```python
# ===== 目的：登録したホットキーとアクションをまとめて解除する =====
import carb

_hotkey_registry.deregister_all_hotkeys_for_extension(EXT_ID)
_action_registry.deregister_all_actions_for_extension(EXT_ID)
carb.log_warn("[hotkey] deregistered")
```

```text
[hotkey] deregistered
```

解除できたことの確認は、矢印キーを押して Console に行が出ないことで判定できる。行が出ないうえにビューポートのカメラ移動が戻っていれば、横取りが解けている。

### ビューポート上に限定する

```python
# ===== 目的：ビューポートにフォーカスがあるときだけ効く矢印キーを登録する =====
import carb
import omni.kit.actions.core
import omni.kit.hotkeys.core
from omni.kit.hotkeys.core import HotkeyFilter

EXT_ID = "demo.joint.hotkeys"
ACTION_ID_UP = "joint_angle_up"

_action_registry = omni.kit.actions.core.get_action_registry()
_hotkey_registry = omni.kit.hotkeys.core.get_hotkey_registry()

_action_registry.register_action(
    EXT_ID, ACTION_ID_UP, lambda: carb.log_warn("[hotkey] 上矢印"), display_name="関節角度 +"
)

_hotkey_registry.register_hotkey(
    EXT_ID,
    "UP",
    EXT_ID,
    ACTION_ID_UP,
    filter=HotkeyFilter(windows=["Viewport"]),
)
carb.log_warn("[hotkey] registered for Viewport only")
```

ビューポートをクリックしてフォーカスを移してから上矢印を押すと行が出る。Script Editor にフォーカスがある状態では出ない。

```text
[hotkey] registered for Viewport only
[hotkey] 上矢印
```

ウィンドウ名が合っていないと、どこにフォーカスがあっても効かない。ビューポートのウィンドウ名はタイトルバーの表示と一致し、2枚目を開くと別の名前になる。名前は次で一覧できる。

```python
import omni.ui as ui
for w in ui.Workspace.get_windows():
    print(w.title)
```

```text
Viewport
Property
Stage
Console
Script Editor
```

### 押しっぱなしで連続的に変えたい場合

矢印キーを押し続けたときに、ホットキーの仕組みが連続して発火するかどうかは、公式ドキュメントに記述がなく【未確認】になる。上のコードで矢印キーを押し続け、行が1回だけ出るか連続で出るかを見れば判定できる。

1回しか出ない場合、連続変化は次の構成で実現する。

1. キーが押されたときにフラグを立て、離されたときに下ろす。
2. アプリの更新イベントで、フラグが立っている間だけ毎フレーム角度を加算する。

更新イベントの購読と解除は [[02_settingsは状態の置き場所]] で使ったものと同じ形になる。

```python
# ===== 目的：毎フレーム処理を回す枠組み（連続変化が必要な場合の受け皿） =====
import carb
import omni.kit.app

_frame_count = 0


def _on_update(event):
    global _frame_count
    _frame_count += 1
    if _frame_count % 60 == 0:
        carb.log_warn(f"[update] {_frame_count} フレーム経過")


_update_sub = omni.kit.app.get_app().get_update_event_stream().create_subscription_to_pop(
    _on_update, name="demo_joint_update"
)
carb.log_warn("[update] started")
```

```text
[update] started
[update] 60 フレーム経過
[update] 120 フレーム経過
```

解除は次のとおり。

```python
_update_sub.unsubscribe()
_update_sub = None
carb.log_warn("[update] stopped")
```

```text
[update] stopped
```

## 理解度確認問題

1. アクションとホットキーを別々の概念に分けてある理由は何か。
2. 同じキーがグローバルとローカルの両方に登録されている場合、どちらが優先されるか。
3. モードから抜けるときに、そのモード用のキー割り当てをまとめて外す方法は何か。

<details>
<summary>解答</summary>

1. 同じ処理をメニュー・ボタン・キーの複数経路から呼べるようにするため。処理の実体を1つに保ち、呼び出し口だけを増やせる。
2. ローカルが優先される。
3. `deregister_all_hotkeys_for_extension(拡張機能のID)` を呼ぶ。登録時に同じ ID を指定しておく必要がある。

</details>
