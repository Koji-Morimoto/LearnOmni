# ツールバーのコンテキスト

## 解決したい課題：作業ごとに道具立てを丸ごと替えたい

ツールバーに置けるボタンの数には限りがある。並進・回転・スケールに加えて、塗装モードのブラシ設定、計測モードの単位切替、自作モードのロボット選択と軸選択をすべて常時並べると、画面が埋まる。

必要なのは「今の作業に関係するボタンだけを出す」仕組みになる。

## 解決の方針：ツールバー自身に「今のモード」を1個持たせる

`omni.kit.window.toolbar` の説明では、この仕組みの目的が「アプリの現在のモードやワークフローに応じて別々の道具立てを表示できるようにし、画面を散らかさずに作業ごとの専用ツールバーを実現すること」とされている [^1]。

この「今のモード」を表す文字列がコンテキストになる。

## 仕組み

### 文字列を持つ主体が2種類ある

| 誰が | いくつ持つか | 何を表すか |
|---|---|---|
| `Toolbar`（ツールバー本体） | 常に1個 | 現在有効なコンテキスト |
| 各 `WidgetGroup` | 登録時に1個 | 自分が属するコンテキスト |

両者が一致するグループが有効になる。この作りから、**コンテキストはグループの識別名ではない**ことが分かる。識別名なら全グループが常に有効なままで、切り替えという概念が生まれない。

グループ名との違いを整理すると次のようになる。

| 観点 | グループの識別名だとしたら | 実際のコンテキスト |
|---|---|---|
| 文字列を持つ主体 | 各グループが自分の名前として1個持つだけ | ツールバーが「現在の1個」を持ち、各グループが「自分の所属1個」を持つ |
| 同時に有効な数 | 全グループが常に有効 | ツールバーの現在値と一致するものだけ |
| 切り替えという操作 | 存在しない | `acquire_toolbar_context(名前)` で行う |
| 目的 | 検索・参照 | 表示と入力の有効範囲を絞る |

近い比喩を1つ挙げると、コンテキストはラジオボタンのグループ名ではなく、**表示中のタブそのもの**になる。各グループは「自分はこのタブに乗る」と宣言し、ツールバーは「今どのタブを開いているか」を1個だけ持つ。

なお、グループの中の個々の部品を名前で引く仕組みは別にあり、`Toolbar.get_widget(name)` がそれになる [^2]。識別名の役割はこちらが担っている。

### 関係する API は4つ

| 呼び出し | 説明 | 出典 |
|---|---|---|
| `Toolbar.add_widget(widget_group, priority, context='')` | 第3引数がそのグループの所属コンテキスト。省略時は既定コンテキスト | [^2] |
| `Toolbar.acquire_toolbar_context(context)` | 現在のコンテキストを切り替える。戻り値は解除用のトークン（整数） | [^2] |
| `Toolbar.release_toolbar_context(token)` | トークンに対応する切り替えを戻す。期限切れのトークンを渡した場合は何もしない | [^2] |
| `Toolbar.get_context()` | 現在のコンテキストを取得する | [^2] |

`acquire_toolbar_context` は、**前の所有者がまだ解放していなくても先に取る**と明記されている [^2]。待たされる排他ロックではなく、後から来たほうが勝つ方式になる。トークンは、奪われた側が後から `release` を呼んでも他人の状態を壊さないようにするための識別子として働く。

`Toolbar` には `DEFAULT_CONTEXT` と `DEFAULT_CONTEXT_TOKEN` という属性もある [^2]。`add_widget` で `context` を省略したときの空文字列が、既定コンテキストに対応する。

### 切り替わった瞬間に何が起きるか

3つのことが起きる。

1. `Toolbar.get_context()` の戻り値が新しい文字列に変わる。
2. 登録済みの各グループの `on_toolbar_context_changed(新しいコンテキスト)` が呼ばれる [^3]。
3. `WidgetGroup` の内部メソッド `_is_in_context()` の戻り値が変わる。これを判定に使っているホットキーの有効・無効が切り替わる。

3つ目は公式のサンプルコードから読み取れる。ホットキーを作る箇所で、有効判定として `_is_in_context` を渡している [^4]。

```python
        self._hotkey = Hotkey(
            "toolbar::test2",
            Key.K,
            lambda: button2.model.set_value(not button2.model.get_value_as_bool()),
            lambda: self._is_in_context(),
        )
```

第4引数が「このホットキーが今有効かどうか」を返す判定関数になる。**自分のグループが現在のコンテキストに属しているときだけ K キーが効く**、という意味になる。

同じサンプルには、ボタンの押下でコンテキストを取りに行く処理も含まれている [^4]。

```python
        def on_value_changed(index, model):
            if model.get_value_as_bool():
                self._acquire_toolbar_context()
            else:
                self._release_toolbar_context()
```

ボタンが押された状態になったらツールバーのコンテキストを自分のものに切り替え、解除されたら戻す、という作りになる。`_acquire_toolbar_context` と `_release_toolbar_context` は `WidgetGroup` の内部メソッドで、トークンの保持を内部で行ってくれる。

### 既定コンテキストのグループが残るかどうか

コンテキストが切り替わったとき、既定コンテキスト（`context` を省略して登録したグループ）が画面に残るのか消えるのかは、公式ドキュメントに記述がなく【未確認】になる。次の実装で確定できる。

## 実装

### 2つのコンテキストに1個ずつボタンを登録して観測する

Script Editor に貼り付ける全文になる。既定コンテキストに1個、独自コンテキストに1個のボタンを登録し、切り替えたときの見え方と通知を観測する。

```python
# ===== 目的：コンテキスト切替で何が起きるかを観測する =====
import carb
import omni.ui as ui
from omni.kit.widget.toolbar import WidgetGroup, get_instance

MY_CONTEXT = "demo_joint_context"


class ProbeGroup(WidgetGroup):
    """ボタン1個を持ち、コンテキスト関連の通知をすべて記録するグループ。"""

    def __init__(self, label: str):
        super().__init__()
        self._label = label
        self._sub = None

    def get_style(self):
        return {}

    def create(self, default_size):
        button = ui.ToolButton(
            name=f"probe_{self._label}",
            text=self._label,
            width=default_size,
            height=default_size,
        )
        self._sub = button.model.subscribe_value_changed_fn(
            lambda model: carb.log_warn(
                f"[{self._label}] clicked = {model.get_value_as_bool()}"
            )
        )
        return {f"probe_{self._label}": button}

    def clean(self):
        self._sub = None
        super().clean()

    def on_added(self, context):
        carb.log_warn(f"[{self._label}] on_added(context={context!r})")

    def on_removed(self):
        carb.log_warn(f"[{self._label}] on_removed()")

    def on_toolbar_context_changed(self, context: str):
        carb.log_warn(
            f"[{self._label}] on_toolbar_context_changed(context={context!r})"
            f"  is_in_context={self._is_in_context()}"
        )


_toolbar = get_instance()

_group_default = ProbeGroup("DEF")   # 既定コンテキストに登録する
_group_custom = ProbeGroup("CTX")    # 独自コンテキストに登録する

_toolbar.add_widget(widget_group=_group_default, priority=200)
_toolbar.add_widget(widget_group=_group_custom, priority=201, context=MY_CONTEXT)

carb.log_warn(f"[probe] current context = {_toolbar.get_context()!r}")
```

実行直後の出力は次のようになる。

```text
[DEF] on_added(context='')
[CTX] on_added(context='demo_joint_context')
[probe] current context = ''
```

続いてコンテキストを切り替える。

```python
# ===== 目的：コンテキストを切り替え、どちらのボタンが残るかを目視する =====
import carb

_token = _toolbar.acquire_toolbar_context(MY_CONTEXT)
carb.log_warn(f"[probe] acquired token = {_token}, context = {_toolbar.get_context()!r}")
```

出力は次のようになる。

```text
[DEF] on_toolbar_context_changed(context='demo_joint_context')  is_in_context=False
[CTX] on_toolbar_context_changed(context='demo_joint_context')  is_in_context=True
[probe] acquired token = <整数>, context = 'demo_joint_context'
```

**この時点でツールバーを目視し、`DEF` と書かれたボタンが残っているか消えているかを記録する。これで未確認事項3が確定する。** 通知の内容は上のとおり両方のグループに届くが、表示がどうなるかは通知からは分からない。

戻すときは取得時のトークンを渡す。

```python
_toolbar.release_toolbar_context(_token)
carb.log_warn(f"[probe] released, context = {_toolbar.get_context()!r}")
```

```text
[DEF] on_toolbar_context_changed(context='')  is_in_context=True
[CTX] on_toolbar_context_changed(context='')  is_in_context=False
[probe] released, context = ''
```

後始末は次のとおり。

```python
for _g in (_group_default, _group_custom):
    _toolbar.remove_widget(_g)
    _g.clean()
del _group_default, _group_custom
```

```text
[DEF] on_removed()
[CTX] on_removed()
```

### 自作モードでの使い分け

| 作りたいもの | コンテキストの扱い |
|---|---|
| モード切替ボタン1個だけを足す | `context` を省略して既定コンテキストに登録する。既存の並進・回転・スケールと横並びになる |
| モード中だけロボット選択・軸選択のボタン列を出す | 独自コンテキストに登録し、モード開始時に `acquire_toolbar_context`、終了時に `release_toolbar_context` を呼ぶ |

後者を選んだ場合、モード終了時の後始末に `release_toolbar_context` が1つ増える。呼び忘れるとツールバーが専用の道具立てのまま戻らなくなる。

## 理解度確認問題

1. コンテキストはグループの識別名か。違うなら、識別名の役割を担う API は何か。
2. 既にコンテキストを取得している別の拡張機能がある状態で `acquire_toolbar_context` を呼ぶと、待たされるか、それとも取れるか。
3. `_is_in_context()` の戻り値は何に使われるか。

<details>
<summary>解答</summary>

1. 識別名ではない。ツールバーが「現在の1個」を持ち、グループが「所属する1個」を持つ状態であり、一致するものだけが有効になる。識別名の役割は `Toolbar.get_widget(name)` が担う。
2. 取れる。前の所有者が解放していなくても先取りする方式になっている。
3. そのグループが現在のコンテキストに属しているかの判定に使う。公式サンプルではホットキーの有効判定に渡している。

</details>
