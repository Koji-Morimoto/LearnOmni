# 07. 構成に参加しない記述

## 1. この章が解く問題

USD ファイルをテキストで開くと、確かに `def Xform "Gripper"` と書かれている。しかしステージ上に `Gripper` が出てこない。

この状況は異常ではなく、**設計上想定された正常な状態**である。ただし原因が5系統あり、どれなのかを切り分けないと対処できない。

---

## 2. 解決の方針: 「ファイルにあること」と「構成に参加すること」を分ける

OpenUSD は、データの存在と、そのデータが合成に参加するかどうかを、意図的に別々に扱う。理由は次の2つである。

- **性能**: 巨大なシーンで、必要ない部分の読み込みを省きたい
- **選択**: 複数の選択肢をファイルに持たせておき、実行時に切り替えたい

この分離があるので、「ファイルには書いてあるが、いまのステージには出てこない」が正常な状態として存在する。

---

## 3. 仕組み: 5つの系統

【確定】ファイルにある記述がステージに現れない原因は、次の5系統で全部である。

### 系統1: Reference / Payload の範囲外

04 で見た通り、Reference は `defaultPrim`（またはパス指定）を入口として、そのプリム以下だけを持ち込む。同じファイルの他のルートレベルのプリムは持ち込まれない。

```usda
# parts.usd
#usda 1.0
(
    defaultPrim = "Gripper"
)

def Xform "Gripper" { }
def Xform "Camera"  { }     # ← Reference では持ち込まれない
def Xform "Sensor"  { }     # ← Reference では持ち込まれない
```

`references = @parts.usd@` と書くと、`Gripper` だけが持ち込まれる。`Camera` と `Sensor` は無視される。

**確認方法**: そのファイルを `Usd.Stage.Open()` で単独で開く。直接開いた場合は `defaultPrim` が無関係になり、ルートレベルのプリムがすべて現れる。

```python
from pxr import Usd
s = Usd.Stage.Open(r"C:\work\parts.usd")
print([p.GetPath() for p in s.GetPseudoRoot().GetChildren()])
```

想定出力:

```text
[Sdf.Path('/Gripper'), Sdf.Path('/Camera'), Sdf.Path('/Sensor')]
```

### 系統2: Payload が未ロード

04 で見た通り、Payload はロードするまで中身が構成されない。

**確認方法**:

```python
from pxr import Usd

stage = Usd.Stage.Open(r"C:\work\scene.usd", Usd.Stage.LoadNone)
print("loaded  :", [str(p) for p in stage.GetLoadSet()])
print("loadable:", [str(p) for p in stage.FindLoadable()])
```

想定出力:

```text
loaded  : []
loadable: ['/World/Robot01', '/World/Robot02']
```

`loadable` に出てくるが `loaded` に出てこないプリムが、未ロードの Payload である。`stage.Load("/World/Robot01")` または `stage.LoadAndUnload({"/World/Robot01"}, {})` で読み込める。

### 系統3: Variant が非選択

04 で見た通り、VariantSets は選択されたバリアントの中身だけを構成する。選ばれなかった方はファイルに存在するが出てこない。

**確認方法**:

```python
prim = stage.GetPrimAtPath("/World/Gripper")
for name in prim.GetVariantSets().GetNames():
    vset = prim.GetVariantSets().GetVariantSet(name)
    print(f"{name}: selected={vset.GetVariantSelection()} choices={vset.GetVariantNames()}")
```

想定出力:

```text
modelVariant: selected=wide choices=['narrow', 'wide']
```

`choices` に出ているのに `selected` でないものが、非選択のバリアントである。

### 系統4: レイヤーが Mute されている

**Mute（ミュート）とは**、レイヤーを一時的に合成から外す機能である。ファイルは存在したまま、そのレイヤーの Spec が全部無視される。

何のためにあるかというと、**レイヤーを削除せずに、あるかないかを比較したい**からである。干渉モデルの案Aと案Bを別レイヤーにして、交互にミュートすれば比較できる。

Mute はステージごとのセッション状態であり、ファイルには保存されない。

**確認方法**:

```python
print("muted:", stage.GetMutedLayers())
```

想定出力:

```text
muted: ['C:/work/collision_planB.usd']
```

`stage.MuteLayer(identifier)` でミュート、`stage.UnmuteLayer(identifier)` で解除する。

### 系統5: `active = false`

**プリムの activation** とは、プリムとその子孫をステージのツリーから外す機能である。`active` はプリムのメタデータで、既定値は `true` である。

Mute との違いは適用の単位である。

- **Mute**: レイヤー単位。そのレイヤーの意見が全部消える
- **`active = false`**: プリム単位。そのプリムと**その子孫全部**がツリーから外れる

```usda
def Xform "Gripper" (
    active = false
)
{
    def Cube "pad" { }
}
```

このとき `Gripper` も `Gripper/pad` も、通常のトラバースに出てこない。

**確認方法**: 既定のトラバースは非アクティブなプリムを飛ばすので、明示的に含める指定が要る。

```python
from pxr import Usd

print("--- 既定のトラバース ---")
for prim in stage.Traverse():
    print(prim.GetPath())

print("--- 非アクティブも含める ---")
for prim in stage.TraverseAll():
    print(prim.GetPath(), "active =", prim.IsActive())
```

想定出力:

```text
--- 既定のトラバース ---
/World
--- 非アクティブも含める ---
/World active = True
/World/Gripper active = False
/World/Gripper/pad active = True
```

`/World/Gripper/pad` 自身は `active = True` なのに既定のトラバースに出てこない点に注意してほしい。親が非アクティブだと、子は自分の設定にかかわらずツリーから外れる。

`prim.SetActive(True)` で戻せる。ただし Edit Target が指すレイヤーに `active = true` の意見が書き込まれるので、書き込み先には注意が要る（06 参照）。

## 4. 実装: 5系統を一括で切り分ける

「ファイルに書いてあるのに出てこない」に遭遇したとき、上から順に確認する診断コードを示す。

```python
from pxr import Usd, Sdf

STAGE_PATH = r"C:\work\scene.usd"
TARGET     = "/World/Gripper"

stage = Usd.Stage.Open(STAGE_PATH)

# 系統4: ミュートされているレイヤーはあるか
muted = list(stage.GetMutedLayers())
print(f"[系統4] muted layers        : {muted}")

# 系統2: 未ロードの Payload はあるか
loadable = {str(p) for p in stage.FindLoadable()}
loaded   = {str(p) for p in stage.GetLoadSet()}
print(f"[系統2] unloaded payloads   : {sorted(loadable - loaded)}")

prim = stage.GetPrimAtPath(TARGET)
if not prim:
    print(f"[系統1] {TARGET} はステージ上に存在しない")
    print("        → Reference の範囲外か、親が未ロードの可能性が高い")
else:
    # 系統5: 非アクティブか
    print(f"[系統5] active              : {prim.IsActive()}")

    # 系統3: 非選択のバリアントはあるか
    for name in prim.GetVariantSets().GetNames():
        vs = prim.GetVariantSets().GetVariantSet(name)
        print(f"[系統3] variantSet {name}: "
              f"selected={vs.GetVariantSelection()} choices={vs.GetVariantNames()}")

    # 系統1: どのレイヤーの意見でできているか
    print("[系統1] prim stack          :")
    for spec in prim.GetPrimStack():
        print(f"          {spec.layer.identifier} {spec.path}")
```

想定出力の例:

```text
[系統4] muted layers        : []
[系統2] unloaded payloads   : ['/World/Robot02']
[系統5] active              : False
[系統3] variantSet modelVariant: selected=wide choices=['narrow', 'wide']
[系統1] prim stack          :
          C:/work/parts.usd /Gripper
```

この出力からは「`Gripper` は `parts.usd` から Reference で来ており、`active = False` なのでツリーに出てこない」と読める。原因は系統5である。

## 5. 5系統の対比表

| 系統 | 単位 | ファイルに保存されるか | 確認する API | 戻し方 |
|---|---|---|---|---|
| 1. Reference / Payload の範囲外 | プリム以下 | される（`references` として） | `prim.GetPrimStack()` | 参照先のパス指定を変える |
| 2. Payload 未ロード | プリム以下 | されない（ロード状態はセッション） | `stage.FindLoadable()` と `stage.GetLoadSet()` | `stage.Load(path)` |
| 3. Variant 非選択 | バリアント単位 | される（`variants` として） | `GetVariantSelection()` | `SetVariantSelection(name)` |
| 4. レイヤー Mute | レイヤー単位 | されない（セッション状態） | `stage.GetMutedLayers()` | `stage.UnmuteLayer(id)` |
| 5. `active = false` | プリムと子孫 | される（プリムのメタデータ） | `prim.IsActive()` | `prim.SetActive(True)` |

「ファイルに保存されるか」の列が重要である。**されない系統（2と4）は、ステージを開き直せば既定状態に戻る。** されるもの（1・3・5）はファイルに残り続けるので、次に開いても同じ状態になる。「昨日は出ていたのに今日は出ない」なら 2 か 4 を、「いつ開いても出ない」なら 1・3・5 を疑う。

## 理解度確認問題

**問1.** `Gripper` の `active` は `True` なのに、既定のトラバースに出てこない。考えられる理由は何か。

<details><summary>解答</summary>

親のプリムが `active = false` になっている。親が非アクティブだと、その子孫は自分の `active` の値にかかわらずツリーから外れる。`stage.TraverseAll()` で全プリムを列挙し、祖先の `IsActive()` を辿れば特定できる。

</details>

**問2.** レイヤーの Mute と `active = false` の違いを2点挙げよ。

<details><summary>解答</summary>

1. **適用の単位**: Mute はレイヤー単位で、そのレイヤーの意見が全部消える。`active = false` はプリム単位で、そのプリムと子孫がツリーから外れる
2. **永続性**: Mute はステージのセッション状態でファイルに保存されない。`active` はプリムのメタデータとしてファイルに保存される

</details>

**問3.** ステージを開き直したら、昨日は見えていなかったプリムが見えるようになった。原因の候補は5系統のうちどれか。

<details><summary>解答</summary>

系統2（Payload 未ロード）か系統4（レイヤー Mute）。この2つはセッション状態でファイルに保存されないため、開き直すと既定状態に戻る。系統1・3・5 はファイルに保存されるので、開き直しただけでは変わらない。

</details>
